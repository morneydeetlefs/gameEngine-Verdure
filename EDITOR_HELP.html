Verdure
World Editor

A browser-based tool for building point-and-click game worlds. Design maps, entities, dialog trees, mini-games, and HUD layouts — then export a complete, deployable game package.

🌱 Version 1.0 · Editor Help · Game-Agnostic Engine

01Overview

The Verdure World Editor is a game-agnostic point-and-click adventure game authoring tool. It produces a folder of JSON files and assets that the Verdure Game Engine reads to run any game you design — from guerrilla gardening to mystery adventures to puzzle games.

🛠
editor/index.html
The World Editor. Runs locally via VS Code Live Server. Reads and writes your project folder directly via the File System Access API.
🎮
game/index.html
The Game Engine. Hosted on the web. Loads your JSON files, renders scenes, handles interactions, dialogs, inventory, timers, and ads.
📁
data/
Your game content. game.json, entities.json, scenes/, dialogs/ — all authored in the editor, read by the engine.
🖼
assets/
Sprites, backgrounds, and audio files. Uploaded via the Assets tab. Referenced by relative path in all JSON files.
✨
What's new in v1.0: The engine is now fully game-agnostic — no Verdure-specific logic is hardcoded. HUD elements, player stats, entity categories, and interaction systems are all configured through JSON. Any point-and-click game can be built on this engine.

File System Access API

The editor uses the browser's File System Access API to read and write files directly in your project folder. This means saves go straight to disk — no downloading and re-importing JSON files. When you click Save, your entities.json updates on disk immediately and Live Server reloads the game automatically.

  1. Open your project in VS Code. File → Open Folder → select your verdure/ project root.
  2. Start Live Server. Right-click editor/index.html in the VS Code file explorer → Open with Live Server. Chrome opens automatically.
  3. Open your project folder. The editor shows an Open Project Folder prompt on first launch. Click it, navigate to your verdure/ folder, and click Select Folder. Chrome asks for permission — click Allow.
  4. Start editing. The editor reads all existing JSON files from the folder. Any saves write back to disk instantly. The folder handle is remembered for the session.
⚠
Chrome only for editing. The File System Access API is supported in Chrome 86+ and Edge 86+. Firefox does not support file writes. You can view the editor in Firefox but saving will fall back to download-only mode.
💡
Re-opening the editor. Chrome remembers the folder permission for the session. If you close and reopen the browser tab, click Reconnect Project Folder and select the same folder — permission is granted instantly without a new dialog.

03Project Structure

The editor expects and maintains this folder structure. When you export or save, files are written to these exact locations.

verdure/ ├── editor/ │ ├── index.html ← World Editor (open this with Live Server) │ ├── css/ ← editor styles │ └── js/ ← editor logic, one file per tab │ ├── game/ │ ├── index.html ← Game Engine (deploy this to your web host) │ ├── css/ │ └── js/ │ ├── shared/ │ ├── renderer.js ← scene rendering (used by editor preview + game) │ └── animations.js ← glow, float, grow, pulse, sparkle │ ├── data/ │ ├── game.json ← HUD config, player setup, ads, audio mapping │ ├── entities.json ← all entity templates │ ├── scenes/ │ │ ├── scene_lot.json │ │ └── scene_shed.json │ └── dialogs/ │ └── botanist_intro.json │ ├── assets/ │ ├── sprites/ ← entity and NPC sprites (PNG) │ ├── backgrounds/ ← scene background images (JPG/PNG) │ ├── audio/ ← ambient loops and SFX (MP3/OGG) │ └── icons/ ← PWA icons (192×192, 512×512 PNG) │ ├── minigames/ │ └── puzzle_box.html ← self-contained mini-game HTML files │ ├── manifest.json ← PWA manifest (installable on mobile + desktop) ├── sw.js ← Service Worker (offline caching) └── EDITOR_HELP.html ← this file
📁
Asset files, not base64. Unlike the previous version, assets are stored as real files in assets/. JSON files reference them by relative path (e.g. "sprite": "assets/sprites/wildflower_bloom.png"). The editor converts uploaded files internally but writes real files to disk on save. This keeps JSON files small and assets replaceable.

05Assets Tab

The Assets tab is your central media library. Every sprite, background, portrait, and audio file used anywhere in the game is uploaded here first. Everything else in the editor references assets by their ID — you never type a file path manually.

Image Library

Click the Images toggle in the left panel to see the image library.

  1. Upload. Drag image files onto the upload zone, or click Browse. Accepts PNG, JPG, WebP, GIF. Multiple files can be dropped at once.
  2. Label and tag. Each upload prompts for a display label and optional tags (e.g. plant, background, portrait, npc). Tags power the pickers elsewhere in the editor.
  3. Confirm. The file is written to assets/sprites/ (or assets/backgrounds/ if tagged background) and its path is stored in the image registry.
ActionHow
Re-label or re-tagClick the pencil icon on any thumbnail
Replace imageClick the thumbnail → Replace File. All references update automatically.
See where usedClick Used in badge on a thumbnail. Lists every entity and scene referencing this asset.
DeleteOnly possible if Used in is empty. The editor prevents deleting referenced assets.
SearchFilter by label text or tag chip in the left panel.
🎨
Recommended image sizes: Backgrounds — 1920×1080 JPG. Sprites — 64×64 to 256×256 PNG with transparency. Portraits — 120×120 PNG. Keeping sprites consistent in size makes z-ordering and scaling predictable.

Audio Library

Click the Audio toggle. The audio library works the same as images but with additional metadata.

FieldDescription
Typeambient — looping background music/atmosphere. sfx — short one-shot sound effects.
LoopToggle on for ambient tracks. Off for SFX.
PreviewClick ▶ to play the audio in the editor without leaving the tab.
VolumeSet a default volume (0.0–1.0) that game.json uses unless overridden per-scene.
⚠
Keep audio files small. Ambient tracks work best as short loops (20–60 seconds) that the engine loops seamlessly. Long uncompressed audio files significantly increase load time. Use 128kbps MP3 for ambient, 64kbps for SFX.

06Game Tab

The Game tab authors game.json — the top-level configuration file that tells the engine everything about your specific game. The engine reads this file first and uses it to configure all other systems.

Metadata & Engine Settings

VersionYour game version string (e.g. 1.0.0).

Player Setup

Defines the player's state at the start of a new game. All stat names you define here become available throughout the editor in effects and conditions.

FieldDescription
Starting StatsAdd any number of named stats with initial values (e.g. coins: 0, health: 100, energy: 10). Stat names are free-form — define what your game needs.
Starting InventoryEntity picker — select items the player begins with.
Starting FlagsAdd boolean flags that are set from the start (unusual — most flags begin as false / unset).

HUD Builder

The HUD is entirely configured here — the engine has no hardcoded HUD elements. Add, remove, and reorder elements using the drag handles. A live preview strip at the right panel shows exactly how the HUD will render in the game.

Dialog Style

Configure the visual appearance of the dialog box — background colour, text colour, border, font size, and whether NPC portraits appear on the left or right. These settings apply globally to all dialogs in the game.

Transition Settings

Choose the scene transition animation (fade, slide_left, slide_up, none) and its duration in milliseconds. Applied to all portal transitions unless overridden per-portal.

Map ambient tracks to scenes and SFX to engine events. Ambient tracks are selected from the Audio Library. SFX events are fixed engine events (item_pickup, dialog_open, etc.) — assign an audio asset to each.

07Entities Tab

Entities are the interactive objects of your game world — plants, NPCs, tools, hazards, portals, mini-games, decorations, and hidden objects. The Entities tab builds entities.json, a library of reusable templates. Scenes then place instances of these templates at specific positions.

📋
Templates vs Instances. An entity template defines everything an object can be and do — all its states, animations, and interactions. A scene instance says "put this template here, starting in this state." One template can be placed as many instances as needed across all scenes.

Creating an Entity

Click + New Entity in the left panel. Fill in the basic fields:

FieldDescription
IDAuto-generated from the name (lowercase, underscores). Can be edited. Must be unique across all entities.
NameDisplay name shown in pickers and debug overlays.
CategoryDetermines the icon shown in lists and filters available in the scene canvas. See Section 17 for all categories.
DescriptionFlavour text. Used in the editor for clarity — not shown in-game unless referenced in a dialog.
Initial StateDropdown of states you define below. The state the entity starts in when a fresh game begins.

States

Every entity has one or more states. A state defines how the entity looks, what animations play, and what the player can do with it. Click + Add State to create one.

State Fields

FieldDescription
State IDUnique within this entity (e.g. seed, sprouting, bloomed).
LabelHuman-readable name shown in debug overlays.
SpriteImage picker — the sprite displayed in this state. Leave blank for invisible states.
AnimationAnimation type and parameters. See Section 16.
TransformScale, anchor point (bottom, center, top), z-index, and flip-x.
On Enter EffectsEffects that fire the moment the entity enters this state. Use for spawning, timers, sounds, stat changes.
On Exit EffectsEffects that fire when leaving this state (less common — useful for cleanup).

Growth Animation (Plants)

When animation type is set to grow, two additional fields appear:

FieldDescription
Grow Axisxy for side-view scenes (grows upward and slightly wider). xz for top-down scenes (grows outward in all directions).
DurationSeconds for the animation to complete. Should match the grow timer duration for perfect sync.

Interactions

Interactions are what the player can do with an entity in a given state — click it, use a tool on it, combine items, or watch an ad for a reward. Each state can have multiple interactions; the engine evaluates conditions top-to-bottom and uses the first one whose conditions all pass.

TypeDescription
clickSimple click with no inventory requirement.
use_itemPlayer must have a specific item selected in inventory. The Requires Item field appears.
combineCombine two inventory items together via the entity. Requires Item specifies the second item.
rewarded_adShows a rewarded ad. Has separate On Rewarded and On Skipped effect lists.

Conditions

Each interaction can have zero or more conditions. All conditions must pass for the interaction to be available. See Section 15 for the full conditions reference.

Effects

Effects are what happens when an interaction fires. Add multiple effects — they execute in order. See Section 14 for the full effects reference.

Timers

A state can have an optional real-time timer that fires when the countdown completes. Timers survive the browser being closed — the engine calculates elapsed time on load and fires immediately if a timer has already completed.

FieldDescription
Timer IDUnique identifier (e.g. wildflower_grow). Used by modify_timer effects to speed up or slow down.
DurationSeconds until the timer fires.
On Complete EffectsEffects that fire when the timer finishes. Typically a set_state to advance the entity.
⏱
Timer tip. The timer starts when the entity enters the state (via on_enter effects using start_timer). If you want a timer that starts immediately when the entity is first placed, set it in the on_enter of the initial state.

08Scenes Tab

Scenes are the maps and rooms of your game. Each scene has a background image, a set of placed entity instances, masks, hotspots, and entry/exit triggers. The Scenes tab provides a visual canvas editor built on Konva.js.

Creating a Scene

Click + New Scene in the left panel. Set the scene name, description, view type (topdown or sideview), and upload a background image via the background picker. The canvas becomes active immediately.

Canvas Toolbar

↖ Select ＋ Place ⬡ Mask ⬟ Hotspot 🖼 Background 👁 Masks 👁 Hotspots 🔍 Preview
ToolHow to use
↖ SelectClick any placed instance, mask, or hotspot to select it. Drag to reposition. Delete removes the selected item. Click empty canvas to deselect.
＋ PlaceClick anywhere on the canvas to open the entity picker. Choose an entity — an instance is placed at the click position. Switch back to Select to reposition.
⬡ MaskClick to place polygon points. Double-click to close the polygon. Esc to cancel. The right panel sets mask type after closing.
⬟ HotspotDrag to draw a rectangular hotspot region. The right panel lets you configure interactions on the hotspot — identical to entity interactions.
🖼 BackgroundOpens the image picker filtered to the background tag. The selected image fills the canvas at 16:9.
👁 Masks / HotspotsToggle visibility of mask overlays and hotspot outlines on the canvas. Useful when positioning instances near masked areas.
🔍 PreviewLaunches the live scene preview in a panel overlay. Shows the scene exactly as the game engine renders it, with animations running.

Placing Instances

Positions are stored as percentages (0–100) of the canvas width and height. This makes scenes resolution-independent — they render correctly on any screen size.

With an instance selected, the right panel shows:

FieldDescription
EntityRead-only. The template this instance was created from.
Position X / YPercentage coordinates. Also updated by dragging on the canvas.
Z-Index OverrideOverride the template's default z-index for this instance. Useful when two instances would otherwise overlap incorrectly.
Scale OverrideScale multiplier for this instance only. Leave blank to use the template's state scale.
Flip XMirror the sprite horizontally. Useful for placing two instances of the same NPC facing different directions.
Initial StateThe state this instance starts in. Defaults to the template's initial_state.

Masks

Masks are polygon regions that restrict interaction or planting. They are visible in the editor as coloured overlays and invisible in-game.

Mask TypeDescription
no_interactClicks inside this region are ignored entirely. Use for walls, sky, water.
no_plantEntities with plant category cannot be placed here. Use for paths, concrete, indoors.

Hotspots

Hotspots are clickable areas defined directly on the background image — no entity sprite needed. Use them for background details: a painted sign, a window, a patch of ground, a bookshelf. They support the full interaction and effects system.

Entry Points

Entry points tell the engine where to focus when arriving in a scene from a specific portal. A default entry point is always required. Add named entry points (e.g. from_shed, from_garden) for portals that arrive from different directions.

Scene On-Enter / On-Exit

Effects that fire when the player enters or leaves the scene. Typically used for first-visit dialogs, ambient sound changes, and flag checks. Multiple trigger blocks can be defined — each block has its own conditions, so different things can happen on the first visit versus subsequent visits.

Scene Preview

Click the 🔍 Preview button to open a live preview overlay. This runs the actual game renderer (shared/renderer.js) against the current scene data, showing sprites at their correct positions with animations playing. What you see in the preview is pixel-perfect to what appears in the game.

🎨
Background image tips. Design backgrounds at 1920×1080 (16:9). Leave intentional blank areas where entities will be placed — sprites sitting on detailed busy backgrounds are hard to read. Slightly desaturated backgrounds make sprites pop. Suggested AI image prompt style: "top-down view of [location], [art style], muted earthy palette, hand-drawn illustration".

09Dialogs Tab

The Dialogs tab builds conversation trees using a visual node graph editor powered by Drawflow. Each dialog is a self-contained JSON file in data/dialogs/. Dialogs can be triggered by entity interactions, hotspots, scene entry events, or other dialogs.

The Node Graph

Each node appears as a card on a zoomable canvas. Connections between nodes are drawn as arrows from the next handle. Click + Add Node to create a node, then drag it to position it. Click Auto Layout to arrange all nodes top-to-bottom automatically.

Node Types

TypeIconDescription
say💬Displays a line of dialog with speaker name and optional portrait. Player clicks to advance. The most common node type.
choice🔀Shows 2–4 buttons for the player to choose from. Each choice has its own conditions, effects, and next pointer. The node has one connection handle per choice.
auto⚡Invisible node — no dialog box shown. Runs effects immediately and jumps to the next node. Use to give items, set flags, or play sounds at precise points in a conversation without interrupting the writing.
end⏹Closes the dialog box. Can have final effects (e.g. set a flag that the conversation is complete). Every dialog tree must have at least one end node.

Say Node Fields

FieldDescription
SpeakerName displayed above the dialog text. Use narrator for voiceover-style text with no portrait.
PortraitImage picker filtered to the portrait tag. Optional — narrator nodes have no portrait.
Portrait Sideleft or right. Swap sides for visual variety in two-character conversations.
TextThe dialog line. Supports variable substitution: {player_name}, {stat_coins}, {stat_health}.
StyleVisual treatment. default — standard dialog box. item_received — golden highlight with item icon. inner_monologue — italic, no border.
EffectsOptional effects that fire when this node is displayed (before the player clicks). Useful for playing a sound or setting a flag on a specific line.

Branching & Choices

Choice nodes branch the conversation. Each choice can have conditions — a choice only appears if all its conditions pass. This allows dialog options to change based on what the player has done.

🌿
Loop back, don't duplicate. If a player asks a side question and you want them to return to the main choice, connect the side branch's end back to the choice node — not to a copy of it. The node graph makes loops like this easy to visualise and avoids duplicate content.
📝
Organizing large dialog trees. Use the Auto Layout button regularly to keep the graph readable. For very long conversations, consider splitting into multiple dialog files linked by show_dialog effects at end nodes.

10Save & Export

Saving During Development

Press Ctrl+S or click Save in the header. All modified JSON files are written directly to your project folder. Live Server detects the changes and reloads game/index.html automatically — your game is updated in seconds.

💡
Keep the game running in a second browser tab alongside the editor. After each Ctrl+S in the editor tab, the game tab reloads automatically. This gives you an instant play-test loop.

Export Zip (Deployment)

Click Export Zip in the header to download a complete, deployable archive of your project. The zip contains:

  • All JSON data files (game.json, entities.json, all scenes, all dialogs)
  • All asset files (assets/sprites/, assets/backgrounds/, assets/audio/)
  • The game engine (game/)
  • The shared renderer (shared/)
  • Mini-games (minigames/)
  • PWA files (manifest.json, sw.js)

The editor itself is not included in the export — it is a development tool and is not deployed.

⚠
Always export a backup zip at the end of every significant session. Commit the zip (or the raw project folder) to GitHub after each milestone. The editor's localStorage autosave is a safety net, not a version history.

11Hosting & PWA Setup

Deploying to the Web

Extract the exported zip and upload its contents to any static web host. The game requires HTTPS for the service worker and ads to function. Recommended free hosts:

HostSetupHTTPS
GitHub PagesPush to a repo, enable Pages in repo settings✓ Automatic
NetlifyDrag the folder onto netlify.com/drop✓ Automatic
VercelConnect GitHub repo or CLI deploy✓ Automatic

Progressive Web App (PWA)

The exported game includes manifest.json and sw.js which make it a fully installable Progressive Web App. After the first online load, the service worker caches all game files and the game plays entirely offline.

What Players Can Do

  • Mobile (iOS/Android): "Add to Home Screen" — the game installs like a native app with a full-screen experience, no browser chrome.
  • Desktop (Chrome/Edge): An install button appears in the address bar — click to install as a standalone desktop app.
  • Offline play: After the first load, the game works with no internet connection on any platform.
ℹ
Updating a published game. When you deploy a new version, increment the cache version in sw.js (e.g. verdure-v1 → verdure-v2). Players who reload the game online will receive the update automatically; their offline cache is replaced.

12Ads in Production

Ads require HTTPS and an active internet connection. The engine handles both gracefully.

  • Online: Rewarded and interstitial ads function normally via your AdMob unit IDs.
  • Offline: The Ad Manager detects navigator.onLine === false. Rewarded ad interactions are hidden from the UI. Interstitial triggers are skipped silently. No errors, no broken buttons.
  • Returning online: Ad UI elements reappear automatically when connectivity is restored.
⚠
Disable Test Mode before publishing. In the Game tab → Ads Config, turn off Test Mode before your final export. Leaving test mode on in production means zero ad revenue. Double-check this before every release build.

13Recommended Workflow

  1. Set up the Assets tab first. Upload all sprites, backgrounds, and audio before touching any other tab. Everything else depends on assets being available in the picker.
  2. Configure the Game tab. Set your game title, define your player stats, build the HUD. This establishes the stat names that effects and conditions can reference everywhere else.
  3. Build the Entity library. Create all entity templates — plants, tools, NPCs, hazards, portals, mini-games. You cannot place what doesn't exist. Start with simple entities (decorations, tools) before tackling complex state machines (growing plants, NPCs with dialog).
  4. Write dialog trees. Create dialog files for your NPCs. Having dialogs done before placing NPCs means you can immediately hook them up in the Entities tab interactions.
  5. Build scenes in logical order. Start with the entry/starting scene. Create connected rooms in the order a new player would encounter them. Upload backgrounds before placing objects — positioning is much easier with the scene visible.
  6. Draw masks after backgrounds. Trace non-interactive areas (walls, sky, water, paths) with the ⬡ Mask tool once the background is in place.
  7. Place instances and hotspots. Use the ＋ Place tool to populate the scene. Position with Select. Add hotspots for background details. Keep z-ordering in mind: background decorations low, ground objects mid, foreground objects high.
  8. Link scenes with portals. Place portal entity instances and configure their transition_scene effects. Test every portal in both directions.
  9. Save and play-test frequently. Ctrl+S → switch to the game tab in the browser → reload. Walk through every interaction, trigger every dialog, test every portal. Fix issues before they compound.
  10. Export zip at the end of every session. Deploy to your web host. Commit to GitHub. Share with testers.
🌱
Start small. Two connected scenes, 6–8 entities, one NPC with a dialog tree, one working interaction loop. A focused small world is more playable than an incomplete large one. Expand once the core loop is satisfying.
